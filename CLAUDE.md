# CLAUDE.md

Mechanical designs for RB-Avionics (https://www.rbavionics.com): 3D-printable
cases, mounts and simulator panels (STL), aluminium cutting profiles (DXF), and
notes on off-the-shelf boxes. The printed RB-01/RB-02 designs mirror the
Thingiverse collection of XIAPROJECTS (the repo owner):
https://www.thingiverse.com/XIAPROJECTS/designs

## Layout

```
RB-xx/                        one folder per product; README.md lists its designs
  <slug>-<thing-id>/          a design published on Thingiverse
    README.md                 hand-written, except the generated parts block
    LICENSE.txt               only for designs by other authors, verbatim
    files/                    STL or other print/cut files
    images/                   Thingiverse renders (named after their STL) and photos
    kicad/<project>/          generated KiCad board template (pro, pcb, sch, meta/info.html)
  <slug>/                     a design not on Thingiverse: same layout
RB-Cockpits/<cockpit>/        generated simulator panels: STL tiles, DXF, FCStd, layout SVG
RB-06/printed-case-*/, RB-02/printed-case-*/, RB-02/round-case-*/, RB-01/glasscockpit-*/
                              generated display cases: STL parts, FCStd, cut-out DXF, PNG views
RB-01/f-16-sidestick-grip/    third-party joystick grip: FCStd, STL parts and views generated from its STEP
README.md                     public index: products table and designs table
LICENSE.md                    license of every RB-Avionics design
tools/import-thing.sh         import or update a Thingiverse ZIP
tools/cockpit_layouts.py      cockpit layouts and cut-out sizes, shared by both generators
tools/cockpit_panels.py       FreeCAD generator of the RB-Cockpits panels
tools/display_case_layouts.py display case dimensions, one Case per folder, shared by both generators
tools/display_cases.py        FreeCAD generator of the display cases
tools/step_check.py           checks a display case against the display's STEP model
tools/joystick_grip.py        FreeCAD generator of the F-16 sidestick grip
tools/freecad_render.py       z-buffer PNG renderer shared by the FreeCAD generators
tools/kicad_templates.py      KiCad generator of every design's board template
tools/stl_slice.py            STL section helper used by the KiCad generator
tools/check.sh                layout and file checks, run before committing
```

## Rules

- Never commit ZIPs (`.gitignore` blocks them). Unpack Thingiverse exports with
  `tools/import-thing.sh`; it extracts to a temp dir and refuses absolute paths,
  `..` and symlinks.
- Never edit STL or DXF content by hand. Case files are exports from CAD tools
  that are not in this repo: a fix means a new export from the designer.
  RB-Cockpits files are generated: change `tools/cockpit_panels.py` and rerun it.
  So are the display cases: change `tools/display_case*.py` and rerun. So is the
  F-16 grip, apart from its two source files: change `tools/joystick_grip.py`.
- Thingiverse `README.txt` is not kept: its content lives in README.md, and
  `tools/check.sh` fails if one reappears.
- Licenses: RB-Avionics designs (XIAPROJECTS, Sandro and the RB-Avionics team,
  the generated cockpits) are free for personal use, commercial use by
  agreement. Their README License row links `LICENSE.md`. A design by another
  author keeps its own `LICENSE.txt` and License row: never relicense it.
  `RB-02/gps-mount-v2-7169108` is by SeeCoryRun under CC BY-SA, which cannot be
  narrowed; keep its author credit everywhere it is listed.
  `RB-01/f-16-sidestick-grip` is by Spock under CC BY-NC-SA 4.0: same rule, and it
  is non-commercial, so RB-Avionics cannot offer a commercial agreement for it and
  it must stay out of paid kits and RB-07.
- Parts installed in an aircraft must withstand 100 °C in cruise on long flights.
  `PRINTING.md` holds the disclaimer, materials table and oven test; every
  printable design README links it (the templates in both tools add the note,
  `tools/check.sh` enforces it). Never recommend PLA, PETG, ABS or ASA for
  aircraft parts; they are fine only for the simulator panels.
- In design README.md files, the blocks between `<!-- BEGIN parts` and
  `<!-- END parts -->` (import script, cockpit and display case generators) and between
  `<!-- BEGIN kicad` and `<!-- END kicad -->` (KiCad generator) are
  regenerated. Edit outside them.
- `kicad/` folders are generated by `tools/kicad_templates.py`: change the script
  and rerun it, never edit the KiCad files by hand. Every board must pass the
  KiCad DRC with 0 errors (the script stops otherwise).
- Folder names are lowercase kebab-case, and Thingiverse folders end in
  `-<thing id>`: that suffix is how a re-import finds the existing folder. No
  spaces anywhere in paths. Part file names stay as Thingiverse exports them.
- Every design must appear in the root README.md designs table and in its
  product README.md; `tools/check.sh` enforces this.
- Commit only when the user asks.

## Workflows

Import a new Thingiverse design, or update one after republishing:

1. On the Thing page, use "Download All Files" to get the ZIP.
2. `tools/import-thing.sh <zip> RB-xx [slug]`. A Thing ID that already has a
   folder is updated in place: `files/` and `images/` are replaced, so removed
   parts disappear; the Thingiverse summary is printed for comparison.
   Review `git status` and `git diff --stat`.
3. For a new design: replace the TODO description in its README.md. Thingiverse
   strips all line breaks from the summary, so restore lists and paragraphs
   while keeping the author's wording. Then add the design to the root README.md
   and to `RB-xx/README.md`.
4. `tools/check.sh` must end with 0 failures.
5. Delete the ZIP.

Change or rebuild a cockpit panel:

1. Edit the layout or the cut-out parameters in `tools/cockpit_layouts.py`
   (print parameters such as thickness and dovetails are in `tools/cockpit_panels.py`). Layout coordinates come from
   `../rb-panel-concept/scene/homecockpit.html` (mm, origin top left, y down);
   comment any deviation from the render.
2. `freecad.cmd tools/cockpit_panels.py` from the repo root (about 2 minutes;
   `RB_ONLY=<prefix>` for one cockpit). FreeCAD is a snap: it cannot see `/tmp`,
   so scripts and outputs it touches must live under `$HOME`. Its command mode
   drops `SystemExit` messages, so the script prints errors itself, and its
   progress output interleaves with the script's lines.
3. Look at every changed `images/layout*.svg`, for example rendered with
   `google-chrome --headless=new --screenshot=<png> --window-size=W,H file://...`.
   Seams must not leave slivers along cut-outs.
4. `tools/check.sh`.

Change or rebuild a display case (the RB-06 printed cases, the RB-02 2.41" case,
the round 1.75" case and the RB-01 GlassCockpit 8" unit and remote round display):

1. Edit the case in `tools/display_case_layouts.py` (display, Pi, AHRS plane,
   carrier openings and recesses, holes) or the shapes in `tools/display_cases.py`.
   Display data come from Waveshare's STEP models: each case's comment says
   which file and how its axes map to the case.
2. `RB_ONLY=<folder> freecad.cmd tools/display_cases.py` from the repo root
   (about a minute a case; all of them take about ten). It stops if a part
   overlaps the display, the Pi, the AHRS board or the room their plugs need,
   and it writes the PNG views with its own z-buffer renderer.
3. Look at the three PNGs in `images/`, then rebuild the board template:
   `RB_ONLY=<folder> python3 tools/kicad_templates.py`.
4. `tools/check.sh`.
5. After a new display or a moved part, check the case against the display's
   STEP model: `RB_ONLY=<folder> STEP=<model.stp> freecad.cmd tools/step_check.py`.
   The models are Waveshare's: they stay out of the repo, under `$HOME`.

Rebuild the F-16 sidestick grip (about a minute):

1. `freecad.cmd tools/joystick_grip.py` from the repo root. `files/Viper_Stick_assem.STEP`
   and `files/Viper_Left.STL` are the author's and stay as published; everything else
   in `files/` and `images/` is generated. The left shell prints from the author's STL
   because one STEP face cannot be meshed: see the script's docstring.
2. Look at the three `images/grip-*.png`, then `tools/check.sh`.

Rebuild the KiCad board templates (after changing a case, a cockpit layout or
the script):

1. `python3 tools/kicad_templates.py` from the repo root, with the system Python
   that has KiCad 9's `pcbnew` module (`RB_ONLY=<path prefix>` for some designs).
   It slices the case STLs at each board plane, writes the projects, runs
   `kicad-cli pcb drc` and draws `images/kicad-<project>.svg` from the saved board.
2. Look at the changed previews; a cockpit layout change needs both generators.
3. `tools/check.sh`.

In FreeCAD's command mode a script argument is imported as a module, so a script
named like a standard module (`socket.py`) silently runs nothing; the snap remaps
`~`, so use absolute paths. On imported STEP solids, `Shape.BoundBox` includes spline
control points and overstates curved parts by tens of mm, and `Shape.Volume` can be
4 % off: measure the mesh instead.

In `pcbnew`'s Python API, `GetLayerID()` wants display names (`User.Drawings`), so
the script uses the layer constants, and there is no `PAGE_INFO`: the paper size
is set in the saved file. A headless `kicad-cli` has no footprint library table,
so its "library not in configuration" warnings are filtered out.

Add a design that is not on Thingiverse: create `RB-xx/<slug>/` with `files/`,
`images/` and a README.md that states author, license, units and material
(sheet thickness for DXF), and links every file and image.

`tools/check.sh` checks: no spaces in paths, no ZIPs, STL files are valid binary
or ASCII STL, files under GitHub's 100 MB limit (warns over 50 MB), relative
links and `<img src>` in Markdown resolve, folder naming, README.md and a License
row linking `LICENSE.md` or the design's `LICENSE.txt`, every design listed in
both indexes, every file and image referenced from its design README, every
`kicad/<project>/` complete and linked from the README.

## Domain notes

- 57 mm and 80 mm are the standard round instrument panel holes (2¼" and 3⅛").
- Measured from the STLs here: the RB-01 drilling template has a Ø79 mm locating
  spigot and M3 pilots at ±31.25 mm; the RB-02 SixPack monitor template has M3
  holes at ±31.0 mm. The cockpit panels use Ø80.5 mm and ±31.125 mm with 3.6 mm
  holes to fit both. The 57 mm screw square (48 mm) comes from the render and is
  unverified.
- RB-01 display windows in the cockpits are the concept render's screen sizes,
  not specific display models.
- Case STLs share one orientation: the front (display side) at low y, z up, so x is
  right as seen from the front. KiCad templates use that view (x right, y up from
  the instrument axis); the cockpit backplanes use panel coordinates (y down).
  Exception: the display case STLs are placed for printing (bezel, carrier and
  shell front face down, rear cover and cap back face down); the case orientation
  is the assembly frame in `tools/display_case_layouts.py` and in the FCStd.
- Waveshare 8DP-CAPLCD, measured from Waveshare's STEP model: glass 194 × 119 mm,
  5.74 mm to the back of the LCD module, 13.67 mm to the back of the HDMI socket.
  The driver board has 4 mm SMD nuts on the Pi pattern (58 × 49) and on 100 × 65,
  but it is held to the LCD only by foam, so the printed case carries the Pi on the
  rear cover instead, and so do the other RB-06 cases.
- `8DP-CAPLCD.stp`'s touch panel solid has a chip block at x -72.9 to -67.4, z 15.7 to 22.2,
  7.46 mm behind the glass front, 1.72 mm proud of the LCD back. The RB-01 GlassCockpit
  carrier has a pocket for it. The RB-06 8" carrier does not: it fails `step_check.py` by
  40 mm3 and needs the same pocket and a rebuild.
- Waveshare 3D models used for the other cases: 6.25inch 720x1560 LCD, 5.5inch HDMI
  AMOLED, 7inch HDMI LCD (C) and 7.9inch HDMI LCD (the last two are single merged
  solids), the 70H-1024600 CT inside Waveshare's own printed shell, and the
  ESP32-S3-Touch-AMOLED-1.75. The 5.5" model has no micro USB sockets (placed from
  the photo); the ESP32-S3-Touch-AMOLED-2.41 has only a drawing; the 13.3inch FHD
  AMOLED has only an outline drawing and photos, so its ports are unverified.
- The display cases too big for a 256 mm bed are cut into pieces at x positions
  that do not line up between bezel, carrier and rear cover (`SPLIT`), so each
  seam is bridged by the next part with screws on both sides.
- RB-02 board planes, measured: SixPack rear module slot on the bar and top bosses
  (4 x M2, 32 x 27.5 mm); front-install case bosses face 17 mm behind its front (a
  block at the top left stands 0.7 mm proud); the Parrot/Compact boxes are rear
  shells around the Waveshare display module. The 98 mm wide shells are the 80 mm
  instruments (2.8" display), the 77 mm wide ones the 57 mm (2.1"), whatever their
  file names say. On the Compact 57 mm shell two bosses sit 2 mm from the wall.
- `RB_Box_WS8inch_v3.dxf` (RB-06) is inconsistent: the vent grid and a push-in
  fitting fall outside the sheet outline and about 20 holes float outside the part.
  The KiCad template draws only the centre face until the designer fixes it.
- In the glider cockpit the RB-05 57 mm shell's GPS hood reaches into the display
  module's space behind the panel (flagged in its backplane notes).
- Displays are Waveshare and Wisecoco. Boards: ESP32 (RB-02, including the 1.75"
  and 2.41" AMOLED boards with their own ESP32-S3; rb-esp supports the 1.75"),
  Raspberry Pi 5 (RB-01, RB-06), Raspberry Pi Zero 2W (RB-03 box).
- RB-01 GlassCockpit: the Waveshare PCIe TO USB 3.2 Gen1 HAT+ is 85 x 56.5 mm with the Pi's
  holes (resellers say 49 mm). Its 40-pin socket is blind, on the underside, so nothing can
  stack above it: the EMS HAT takes the GPIO and the USB HAT goes under the Pi, off the GPIO,
  on its PCIe ribbon and USB-C, which its STEP model omits. That needs `dtparam=pciex1`, and
  the stack stands component faces to the front (`STACK` in the layouts mirrors `pi_xz`).
  The list of USB devices is 11 for 8 ports: a four-port hub, no spare.
- Round RB-01 display: Wisecoco 2.8" with an HDMI driver board, 48 x 48 mm, holes 42 x 44.9
  mm, measured on the RB01.05 sled; sockets from `../www.rbavionics.com/js/rb-01-3d.js`,
  which also has the sizes of the converter, hub, sticks and GPS. Its flex is 18 mm wide:
  the driver board must stay square to it, so parallel to the display or on the sled.
- RB-01 reads a stick or keypad as a keyboard: `main/keypad.go` in `../roastbeef` opens
  only a device whose name contains `keyboard`, and it stops for good when that device
  disconnects. The key map is its `web/settings/keypad.json`.
- RB-01 part names are Italian; the glossary is in
  `RB-01/3d-synthview-7162277/README.md`.

## Related repos (siblings in ../)

  RB-02 build guide.

  wiki has the build examples linked from the READMEs.
- `../www.rbavionics.com`: the public website; `assets/img/sim/` has the cockpit
  concept renders copied into `RB-Cockpits/*/images/concept.webp`.

- `../pcb`: PCB designs (`rb01hat`).
- `../rbsimulator`: drives the instruments from flight simulators.
